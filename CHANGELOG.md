# Changelog

Release notes for the shared workflows in this repository. Site owners: read
these to decide whether you need to pin away from `@v1`.

Entries from the next release onward are generated by
[release-please](.github/workflows/release-please.yml) from conventional commit
messages. The two below were written by hand, before that automation existed.

## [1.1.0](https://github.com/434marketing/.github/compare/v1.0.0...v1.1.0) (2026-08-26)

### Features

* Reference the shared workflows by a floating `v<major>` tag. Sites now use
  `@v1` instead of `@main`, so a breaking change can never reach a site that
  has not opted into it ([#7](https://github.com/434marketing/.github/pull/7))
* Move the `v<major>` tag automatically when a release tag is pushed
  ([#7](https://github.com/434marketing/.github/pull/7))

### Bug Fixes

* Exclude build config (`package.json`, lockfiles, `vite.config.js`,
  `webpack.mix.js`, `gulpfile.js`, `postcss.config.js`, `node_modules`) from
  WP Engine deploys ([#6](https://github.com/434marketing/.github/pull/6))

### Documentation

* Document the versioning contract and what counts as a breaking change
  ([#7](https://github.com/434marketing/.github/pull/7))

## 1.0.0 (2026-04-06)

### Features

* Reusable WP Engine staging and production deploy workflows, plus the
  `workflow-templates/` starter files that call them
  ([#1](https://github.com/434marketing/.github/pull/1),
  [#3](https://github.com/434marketing/.github/pull/3))
* Production deploys take a pre-deploy WP Engine backup and cut a versioned
  GitHub Release in the calling site's repo
  ([#1](https://github.com/434marketing/.github/pull/1))

### Bug Fixes

* Correct the backup notification email variable
  ([#5](https://github.com/434marketing/.github/pull/5))
